** About
:PROPERTIES:
:CUSTOM_ID: about
:END:

#+begin_quote
/Yee(t) (You)Tube/
#+end_quote

This package provides the ability to scrape YouTube, with the results
displayed in a tabulated list.

Core features include:

- Executing queries on YouTube
- Playing & Downloading video(s)
- Pagination for loading more results
- Popup menus for quick access to all commands, via [[https://elpa.gnu.org/packages/keymap-popup.html][keymap-popup]]
- Org-link integration for videos & playlists
- A standalone, minimalist yt-dlp wrapper

Search and channel results come directly from YouTube HTML and JSON,
without an API key.  =yeetube-browse-url= opens the selected item in a
browser through an instance from =yeetube-youtube-invidious-instances=;
it does not use Invidious for searches.

** Usage
:PROPERTIES:
:CUSTOM_ID: usage
:END:

- =M-x yeetube= opens the popup menu with search, download and settings
- =M-x yeetube-search= to search directly
- In the results buffer, press =h= to see all available keybindings

Settings like results limit, video quality, download directory and
audio format live in a settings submenu: press =o= (in the results
buffer or inside the popup) to enter it.  Each entry shows its
current per-buffer value inline and the menu stays open while you
adjust values; =q= returns to the main popup.

** Configuration
:PROPERTIES:
:CUSTOM_ID: configuration
:END:
*** Media Player
:PROPERTIES:
:CUSTOM_ID: media-player
:END:
By default =yeetube-play-function= is set to =yeetube-mpv-play=, you can
use [[https://github.com/kljohann/mpv.el][mpv.el]],
[[https://www.gnu.org/software/emms/][GNU/Emms]] or other similar
packages like so:

#+begin_src emacs-lisp
(setf yeetube-play-function #'emms-play-url)
#+end_src

Make sure that the media player of your choice can directly play
youtube urls.

*** Thumbnails
:PROPERTIES:
:CUSTOM_ID: thumbnails
:END:
Disable thumbnails:

#+begin_src emacs-lisp
(setf yeetube-display-thumbnails-p nil)
#+end_src

*** Apply Filters
:PROPERTIES:
:CUSTOM_ID: apply-filters
:END:
To filter the search results based on a specific criterion, you can
modify the =yeetube-youtube-filter= value to your preferred option.

For example:

#+begin_src emacs-lisp
(setf yeetube-youtube-filter "Views")
#+end_src

This will filter & sort the search results according to the number of views.

*** Results Limit
:PROPERTIES:
:CUSTOM_ID: results-limit
:END:
By default, yeetube fetches 20 results per search.  You can change this:

#+begin_src emacs-lisp
(setf yeetube-results-limit 50)
#+end_src

You can also change it per-buffer via the settings submenu (=o= then
=l=).  When the limit exceeds results on one page, additional pages
are fetched automatically.

*** Tor & torsocks support
:PROPERTIES:
:CUSTOM_ID: tor-torsocks-support
:END:
Tor routing for Emacs HTTP(S) retrieval is currently unsupported.
With =yeetube-enable-tor= non-nil, YeeTube rejects searches, page/feed
fetches and thumbnail requests before entering Emacs URL networking.
HTTPS selects its own TLS transport and existing connections can bypass
SOCKS gateway selection; setting a SOCKS gateway alone is not safe.
Plain HTTP is also rejected because it can redirect to HTTPS.  No request
is silently retried through native networking.

To intentionally use native Emacs URL networking (without a YeeTube Tor
guarantee), leave the default or explicitly set:

#+begin_src emacs-lisp
(setq yeetube-enable-tor nil)
#+end_src

The policy is checked at submission: rejected Tor thumbnails are never
queued, and already accepted native jobs are not rerouted by later option
changes.  Unrelated Emacs networking is unaffected.

For external downloads, =yeetube-enable-tor= still selects the =torsocks=
wrapper.  The separate mpv torsocks toggle is available per-buffer in the
settings submenu (=o= then =t=).  Neither wrapper enables Tor support for
Emacs URL retrieval; configure Tor/torsocks separately for those external
tools.

*** Org links
:PROPERTIES:
:CUSTOM_ID: org-links
:END:
The optional =yeetube-ol= module adds the =yt-video:= and
=yt-playlist:= org-link types: store a link to the entry at point
with =org-store-link=, follow it to play the video (or open the
playlist), and export it as a regular YouTube URL.  To activate:

#+begin_src emacs-lisp
(with-eval-after-load 'org (require 'yeetube-ol))
#+end_src

** Development
:PROPERTIES:
:CUSTOM_ID: development
:END:
The repository ships a Nix flake providing Emacs with all
dependencies.  =make compile=, =make test= and =make lint= re-enter
themselves through =nix develop= when =nix= is available; =make dev=
runs all three.  Byte-compilation warnings and checkdoc diagnostics fail
the build.  =nix flake check --no-write-lock-file= runs the same compile,
lint and ERT gates in an isolated Nix build, using pinned dependencies.
Source, test and fixture files are listed in the Makefile's =SRCS=,
=TESTS= and =FIXTURES= manifests; add new files there so Nix includes them.

=make test-matrix= tests exact Emacs 29.1, the pinned nixpkgs default,
and *Thanos Emacs fork*.  Thanos uses his own installed Emacs fork; run
outside Nix, optionally with =THANOS_EMACS=/absolute/path/to/emacs=.
=make test TESTS=test/yeetube-scraper-tests.el= keeps focused runs available.
=make test-matrix-negative= checks rejection of a version-only executable.

=make load= removes local bytecode and reloads source modules in dependency
order through =emacsclient=.  It stops on the first failure and only reports
success after all modules load and buffer keymaps are refreshed.  This
changes the running Emacs session; it is not a test gate or an atomic reload,
and a failure can leave earlier modules loaded.
